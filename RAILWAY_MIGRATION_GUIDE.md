# Railway Project Migration Guide

## Overview
This guide will help you migrate your KnowledgeBot backend from one Railway project to another.

## Source Project
- **Token**: `19719468-25dc-4b99-9715-5a0540bca7f4`

## Target Project
- **Token**: `0ed75b44-58cd-47b0-9520-6888f4592121`

## Prerequisites
1. Railway CLI installed: `npm install -g @railway/cli`
2. Access to both Railway projects
3. PostgreSQL client tools (`pg_dump`, `pg_restore`, or Railway CLI)

## Migration Steps

### Step 1: Install Railway CLI (if not already installed)
```bash
npm install -g @railway/cli
```

### Step 2: Authenticate with Railway
```bash
railway login
```

### Step 3: Link to Source Project
```bash
railway link --project 19719468-25dc-4b99-9715-5a0540bca7f4
```

### Step 4: Export Database Schema and Data

#### Option A: Using Railway CLI (Recommended)
```bash
# Connect to source database
railway connect postgres

# Export schema only
pg_dump --schema-only --no-owner --no-privileges > schema_backup.sql

# Export data only (excluding schema)
pg_dump --data-only --no-owner --no-privileges > data_backup.sql

# Or export everything together
pg_dump --no-owner --no-privileges > full_backup.sql
```

#### Option B: Using pg_dump directly
```bash
# Get source database URL from Railway dashboard or environment
SOURCE_DB_URL="postgresql://..."

# Export full backup
pg_dump "$SOURCE_DB_URL" --no-owner --no-privileges > full_backup.sql
```

### Step 5: Switch to Target Project
```bash
railway link --project 0ed75b44-58cd-47b0-9520-6888f4592121
```

### Step 6: Deploy Application to Target Project

#### Option A: Deploy from GitHub
1. Go to Railway dashboard
2. Create new project from GitHub repository
3. Select the `knowledgebot-railway-backend` repository
4. Configure environment variables (see Step 7)

#### Option B: Deploy via Railway CLI
```bash
# Initialize new project
railway init

# Link to existing GitHub repo (if available)
railway connect github

# Or deploy directly
railway deploy
```

### Step 7: Configure Environment Variables in Target Project

Set these environment variables in the target Railway project:

```bash
# Database (will be auto-generated by Railway)
DATABASE_URL=postgresql://...

# Firebase Configuration (copy from source)
FIREBASE_PROJECT_ID=your-project-id
FIREBASE_PRIVATE_KEY_ID=your-key-id
FIREBASE_PRIVATE_KEY=your-private-key
FIREBASE_CLIENT_EMAIL=your-client-email
FIREBASE_CLIENT_ID=your-client-id
FIREBASE_AUTH_URI=https://accounts.google.com/o/oauth2/auth
FIREBASE_TOKEN_URI=https://oauth2.googleapis.com/token
FIREBASE_AUTH_PROVIDER_CERT_URL=https://www.googleapis.com/oauth2/v1/certs
FIREBASE_CLIENT_CERT_URL=your-cert-url

# Email OAuth (copy from source)
EMAIL_CLIENT_ID=your-email-client-id
EMAIL_CLIENT_SECRET=your-email-client-secret
EMAIL_REFRESH_TOKEN=your-email-refresh-token

# Other environment variables (copy from source)
AWS_REGION=your-aws-region
AWS_ACCESS_KEY_ID=your-access-key
AWS_SECRET_ACCESS_KEY=your-secret-key
CLOUDFLARE_R2_ACCESS_KEY_ID=your-r2-key
CLOUDFLARE_R2_SECRET_ACCESS_KEY=your-r2-secret
CLOUDFLARE_R2_ACCOUNT_ID=your-account-id
CLOUDFLARE_R2_BUCKET_NAME=your-bucket
```

### Step 8: Restore Database in Target Project

#### Option A: Using Railway CLI
```bash
# Connect to target database
railway connect postgres

# Restore schema first
psql < schema_backup.sql

# Then restore data
psql < data_backup.sql
```

#### Option B: Using Target Database URL
```bash
# Get target database URL from Railway dashboard
TARGET_DB_URL="postgresql://..."

# Restore full backup
psql "$TARGET_DB_URL" < full_backup.sql
```

### Step 9: Run Schema Migration (if needed)
```bash
# Connect to target database
railway connect postgres

# Run the 3NF schema if starting fresh
psql < sql/schema_3nf.sql

# Run admin setup
psql < sql/setup_first_admin_secure.sql
```

### Step 10: Update Frontend Environment Variables

Update your frontend project to point to the new backend URL:

```javascript
// Update API_BASE_URL in frontend config
const API_BASE_URL = 'https://your-new-railway-app-url.up.railway.app';
```

### Step 11: Test the Migration

1. **Test Database Connection:**
   ```bash
   railway run python -c "import os; from shared.db import get_db_connection; print('DB connected' if get_db_connection() else 'DB failed')"
   ```

2. **Test API Endpoints:**
   - Health check: `GET /api/v1/health`
   - Admin login: Test with created admin credentials

3. **Test Frontend Integration:**
   - Widget loading
   - Chat functionality
   - Admin panel access

### Step 12: Cleanup

1. **Keep Source Project Running** until fully tested
2. **Update DNS/Redirects** if using custom domains
3. **Notify Users** of any downtime
4. **Delete Source Project** once migration is confirmed working

## Troubleshooting

### Common Issues:

1. **Database Connection Issues:**
   ```bash
   # Check database URL
   railway variables get DATABASE_URL
   ```

2. **Migration Errors:**
   ```bash
   # Check database logs
   railway logs --service postgres
   ```

3. **Application Startup Issues:**
   ```bash
   # Check application logs
   railway logs
   ```

### Rollback Plan:
- Keep source project active during testing
- Document all environment variables
- Have database backup ready
