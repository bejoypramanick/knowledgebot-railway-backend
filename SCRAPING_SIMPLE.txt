                             WHAT THE USER DOES
                             ══════════════════

    User in Web UI:

    [Knowledge Base]  [Add Website]  [Delete]
                           │
                           ▼
                    Enters: https://example.com

                           │

                    ✓ About Us
                    ✓ Contact Page
                    ✓ Products

                          THE 4 STEPS FOR EACH PAGE

    Page:  https://example.com/about
    ___________________________________


    ┌───────────────────────────────────────────────────────────────┐
    │ STEP 1: FETCH                                                 │
    │ ─────────                                                     │

    │ ──────────                                                    │
    │ Convert HTML to readable Markdown text                       │

    │                                                               │
    │ Input:  HTML (from Step 1)                                   │
    │ Output: Markdown text                                        │
    │                                                               │
    │ # About Us                                                    │
    │                                                               │
    │ We are a company...                                           │
    │                                                               │
    │ ## Our Values                                                 │
    │                                                               │
    │ - Quality                                                     │
    │ - Innovation                                                  │

                                ▼
    ┌───────────────────────────────────────────────────────────────┐
    │ STEP 3: UPLOAD                                                │
    │ ───────────                                                   │
    │ Send the Markdown to Gemini FileSearch                        │
    │ Gemini indexes it for RAG search                              │
    │                                                               │
    │ Input:  Markdown (from Step 2)                               │
    │ Output: document_id                                          │

    │ ──────────                                                    │

                             MEMORY MAGIC
                             ════════════

    OLD WAY (Bad ✗):
    ──────────────

    Step 1: Fetch ALL 100 pages         → 500 MB in memory
    Step 2: Convert ALL 100 pages       → still 500 MB in memory!
    Step 3: Upload ALL 100 pages        → still 500 MB in memory!
    Step 4: Record ALL 100 pages        → finally released

    Memory used: 500 MB (throughout entire process)


    NEW WAY (Good ✓):
    ────────────────

    Page 1:
      - Fetch page 1 (150 KB)
      - Convert page 1 (150 KB)
      - Upload page 1 (150 KB)
      - Record page 1
      - DELETE from memory ✓

    Page 2:
      - Fetch page 2 (150 KB)
      - Convert page 2 (150 KB)
      - Upload page 2 (150 KB)
      - Record page 2
      - DELETE from memory ✓

    Page 3-100: repeat...

    Memory used: ~150 KB (constant, reused)


    RESULT: 100x LESS MEMORY! ✓
    From 500 MB → 5 MB


═════════════════════════════════════════════════════════════════════════════════


                            ERROR HANDLING
                            ══════════════

    What if page fails to upload?
    ────────────────────────────

    Page 3 Upload FAILS:
         │
         ▼
    Log: "⚠️ Upload failed, skipping this page"
         │
         ▼
    Continue to Page 4 (don't stop)
         │
         ▼
    Final count: 47 pages uploaded (not 48)
         │
         ▼
    User sees: "Completed: 47 pages"


    What if admin clicks "Delete All"?
    ──────────────────────────────────

    Delete All button
         │
         ▼
    Set Redis flag: "task_cancelled:abc123xyz"
         │
         ▼
    celery-web-worker CHECKS flag
         │
         ├─ If checking before fetch: Stop immediately
         ├─ If checking at loop start: Stop immediately
         ├─ If checking during upload: Stop immediately
         │
         ▼
    Task stops, partial count recorded
         │
         ▼
    No stale data inserted to database

                            TIMELINE
                            ════════

    t=0s    User clicks "Start Crawling"
    t=0s    API returns "Started" message
    t=1s    Worker picks up task
    t=2s    Fetches first 5 pages (in parallel, max_concurrent=10)
    t=5s    First page uploaded to Gemini
    t=10s   First 10 pages uploaded
    t=20s   First 25 pages uploaded
    t=30s   All 47 pages processed
            Finalization: Update parent record
    t=31s   Publish to Redis
    t=32s   User refreshes knowledge base
            "Knowledge base updated: 47 pages"


═════════════════════════════════════════════════════════════════════════════════


                            KEY METHODS
                            ══════════

    User → API → Worker → ProcessingService

    Main methods (in order):

    1. process_website_content()          [Entry point]
    2. _resolve_file_search_store()       [Setup: get Gemini store]
    3. _resolve_user_role_id()            [Setup: get user]
    4. _stream_pages_through_pipeline()   [Main loop]
       └─ _crawl_pages()                  [BFS: get URL + HTML]
       └─ _process_page_content()         [Convert: HTML → MD]
       └─ _upload_page_to_gemini()        [Upload: MD → Gemini]
       └─ _record_child_page()            [Record: save to DB]
    5. _finalize_website_record()         [Update parent stats]
    6. _publish_success_result()          [Notify Redis]
    7. UI refresh shows results           [User sees new content]
