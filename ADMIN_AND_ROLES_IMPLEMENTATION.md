# Admin Management and Roles Implementation Guide

## Overview
This document outlines the implementation of:
1. Email-based admin management with verification
2. Role-based access control (Admin, HumanAgent, User)
3. Human agent login with email+password or Google auth
4. Token usage display fixes

## Database Migration

### Step 1: Run Admin and Roles Migration
```bash
# Connect to your PostgreSQL database and run:
psql $DATABASE_URL -f sql/admin_and_roles_migration.sql
```

This migration:
- Creates `admins` table for email-based admin management
- Adds `role` column to `human_agents` table
- Creates helper functions and views for role lookup
- Migrates existing admin_user to admins table

## Backend Changes

### 1. Admin Management Endpoints
**File**: `services/configuration_service/admin_management.py`

New endpoints:
- `POST /api/v1/admin/admins` - Add new admins (requires admin role)
- `POST /api/v1/admin/admins/confirm` - Confirm admin via token
- `GET /api/v1/admin/admins` - List all admins (requires admin role)
- `DELETE /api/v1/admin/admins/{email}` - Remove admin (requires admin role)
- `GET /api/v1/admin/user-role/{email}` - Get user role

### 2. Email Service Updates
**File**: `shared/email_service.py`

Added methods:
- `send_admin_confirmation_email()` - Sends confirmation email to new admins
- `send_admin_removal_email()` - Sends removal notification to admins

### 3. Auth Service Updates
**File**: `services/configuration_service/auth.py`

Updated to:
- Determine user role from database (admins/human_agents tables)
- Return role in `/me` endpoint
- Sync role to Firestore on login

### 4. Token Usage Fix
**File**: `services/configuration_service/token_usage.py`

The token usage endpoint (`/api/v1/admin/token-usage`) should:
1. Check `token_usage_cache` table first
2. Fallback to `chatbot_configuration` table
3. Return actual usage values

**Issue**: Token tracking might not be working. Check:
- `shared/token_tracker.py` is being called after API responses
- Token usage is being accumulated in database
- Cache is being updated
